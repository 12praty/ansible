Ansible
=========
==>ansible is open source automation tool used for configuation management,
	application deployment, orchestration, and IT infrastructure automation.
==>it is devloped in python language.
==>control node:where ansible is installed and command are executed.
==>Manage nodes:system being configured.
==>inventory-list of managed node.
==>playbook:file containing automation instrution (written in YAML).

ansible ad-Hoc command
-----------------------
==>we have many module in ansible to perform configuation management
	->ping
	->shell
	->copy
	->yum 
	->service

==>Ping module:check connectivity between the control node and managed node.
	->$ ansible all -m ping

shell module:execute shell command in managed nodes

	-->ansible dbservers -m shell -a uptime

yum module(for RHEL/centOS):install update or remove package

	-->ansible webservers -m yum -a "name=git state=present"
	-->ansible webservers -m yum -b -a "name=git state present"
	-->ansible webservers -m yum -b -a "name=httpd state present"

	-m:specifies the module
	-a:specifies the module argument
	-b:runs with become (sudo) previleges

---------------------------------------------
==> Service Module

Manages services (start/stop/restart).

ansible webservers -b -m service -a "name=httpd state=started"
ansible webservers -b -m service -a "name=httpd state=restarted"

-------------------------------------

==> Copy Module

Copies files from control node to managed nodes.

ansible webservers -m copy -a "src=/tmp/index.html dest=/var/www/html/index.html"

Writing Playbook
================
it contains three section
->host section:represent target manchine. this config depends on ansible inventory 
	file.
->varible section:used to declare variables required in playbook execution.
->task section:define the task activity/opearation which we want to perform on 
	managed node in ansible.

==>playbook to ping all nodes
	------
	- hosts: all
	  tasks:
	  - name: ping all managed nodes
	    ping:
	    remote_user: ansible
	-------
==>command to run:ansible-playbook <playbook-filename> "ansible-playbook 
	01-ping.yml"
	ansible-playbook <playbook-filename> -v (detailed information)
	ansible-playbook <playbook-filename> -vv (detailed information include extra task such as debugging, such as variable values and more descriptive output).
	ansible-playbook <playbook-filename> -vvv (maximum vebrosity, include connection level debugging like full ssh communication "used for deep debugging" ).
	make ansible run verbose mode it shows more detail about what's happening
	during execution.
==>some more command:
	->ansible-playbook 01-ping.yml --syntax-check (check systax)
	->ansible-playbook 01-ping.yml --list-hosts (display info about host to be affcted by playbook)
	->ansible-playbook 01-ping.yml --check (dry run)
	->ansible-playbook 01-ping.yml --step (confim each task before execution)

Handelers And Tags
==================
==>usually in any playbook all the task get executed by default in sequential 
   order and using the concept of handelers we can execute tasks based on other 
   task status.
   ex:if first task status get change only then execute second task.
-->command:ansible-playbook 05-tags.yml --tags "install"
           ansible-playbook 05-tags.yml --skip-tags "install,copy"
           ansible-playbook 05-tags.yml --list-tags

Variables
==========
variable are used to store data
=>we have 4 ways to use variable in ansible
  ->runtime variable
  ->playbook variable
  ->group variable:server specfic variable
  ->hosts variable:in each server there are many host so this is host specfic

==>runtime:pass the var at the time of executing
   ----------
   - hosts: webservers
  become: true

  tasks:
    - name: install httpd package
      yum:
        name: {{"package_name"}}
        state: latest
      tags: install
        - install

    - name: copy index.html file
      copy:
        src: index.html
        dest: /var/www/html/index.html
      tags: copy
        - copy
      notify:
        - start httpd server

  handlers:
    - name: start httpd server
      service:
        name: {{"package_name"}}
        state: started
 ----------------------------
 ==>command: ansible-playbook 06-runtime-variable.yml --extra-vars 
 			 package_name=httpd


==>playbook:inside playbook
---------------
---
- hosts: webservers
  become: true

  vars:
    package_name: httpd

  tasks:
    - name: install httpd package
      yum:
        name: "{{ package_name }}"
        state: latest
      tags:
        - install

    - name: copy index.html file
      copy:
        src: index.html
        dest: /var/www/html/index.html
      tags:
        - copy
      notify:
        - start httpd server

  handlers:
    - name: start httpd server
      service:
        name: "{{ package_name }}"
        state: started
